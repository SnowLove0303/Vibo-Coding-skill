# 资源线程与项目资料包协同技能

## 核心原则

每个项目只维护一份资料包事实清单，不让四个线程各自复制项目说明。资料包指向真实资料和证据，不复制代码、凭据、Cookie、密码、完整日志或聊天历史。Global Memory 是全局限制，不写入项目资料包作为可变事实。

资源线程负责维护项目事实源、资料索引、功能基线、历史用户入口清单、核心流程清单、变更记录、资料陈旧项、可复用资源和跨线程资料包。资源线程只沉淀和核验证据，不替需求与审计线程裁定需求/放行，不替技术执行开发线程实现代码，不替人事部线程决定线程占用或任务派发。

默认资料包根目录为 F:\正式项目与模块化内容\项目资料包。不得在 C 盘创建项目资料包、缓存或验证产物。AIstudy 是长期阅读与知识中转层；当前 RAG 未配置、正文缺失或快照过期时，必须如实标记，不能称为已向量化或已同步。

本技能的 PowerShell 脚本必须保存为 UTF-8 with BOM，以兼容 Windows PowerShell 5；Markdown、JSON 和 AIstudy 文本按其各自约定读取，不能混用编码假设。

## 四线程写入边界

| 分区 | 责任线程 | 可写事实 |
| --- | --- | --- |
| 协作与资料索引 | 人事部 | 资料来源、读取状态、线程状态、交接、资料陈旧和同步待办。 |
| 需求与质量 | 需求与审计 | 需求来源、范围、验收、审计、缺陷、阻断、人工测试和交付状态。 |
| 技术与运行 | 技术开发 | 源码模块、Git 基线、数据/接口契约、运行入口、真实测试证据、回滚点和已验证运行事实。 |
| 资源与功能基线 | 资源线程 | 上一正式可用版本功能基线、历史用户入口清单、核心流程清单、资料索引、可复用资源、已授权变更/废弃记录和事实源恢复规则。 |

不得跨区替他人作结论。人事部不判断需求或代码通过；技术线程不自行改变需求/放行；需求与审计线程不把未核验的技术自报写成事实；资源线程不把资料收集包装成需求完成、开发完成或审计通过。

## 生命周期

1. 初始化：新项目或尚无资料包时，运行 scripts/Initialize-ProjectKnowledgePack.ps1。只输入真实项目名称和真实根目录；脚本读取 Git 基线并创建 manifest.json，不虚构模块、需求或状态。
2. 创建线程与自动维护：人事部每次创建项目线程前必须先运行 Test-ProjectKnowledgePack，随后用 Get-ThreadKnowledgeBundle 按目标职责生成资料清单；线程创建成功后立刻用 Register-ProjectKnowledgePackDispatch 写入真实 ThreadId、分区、派发时间和深度遍历待回执状态。不得只发送聊天摘要或让新线程自行猜资料位置。
3. 深度接收：新线程必须先读取 manifest.json、最近变更记录、资料陈旧项、全局限制和本职责 AIstudy 正文，再对所有项目资料源执行完整结构遍历。技术与需求审计线程还必须深入读取入口、核心模块、Git、数据存储、运行入口、测试和历史审计；资源线程必须核验功能基线、历史入口、核心流程、变更/废弃授权和可复用资料是否完整；人事部必须核验目录遍历和资料覆盖是否真实完成。未提交接收报告前不得接正式任务。
4. 变更：任务结束或发现事实变化时，由对应责任线程在 changes 目录新增一张资料变更单。使用 references/change-record.md 的字段，必须包含证据位置、影响分区、同步对象、未验证项和风险。
5. 核验：人事部在派发/交接前，技术线程在交付待审前，需求与审计线程在审计前，均运行 scripts/Test-ProjectKnowledgePack.ps1。它只读检查根目录、Git 基线、资料路径和资料包结构，不自动修改任何事实。
6. 同步：需求与审计线程决定哪些已证实事实可进入 AIstudy；人事部登记待同步项与接收确认。只有得到用户授权才编辑 AIstudy，编辑后回读、格式化并更新变更单。

## 新线程资料包派发硬规则

人事部必须按 hr、requirements-audit、development、resource 四类职责发放不同的资料清单，且每一份都包含：Global Memory、当前 manifest、最近变更单、所有真实项目资料源、AIstudy 标准化开发流程总控、职责专属节点、当前 Git/运行基线和已知冲突。资料包可以按职责减少无关正文，但不能减少项目完整结构遍历、适用 AGENTS.md、README/入口、Git 状态、数据/运行事实和当前任务相关资料。

涉及版本开发、审计、打包或发布时，资料包必须额外包含上一正式可用版本功能基线、本次新增/变更需求清单、已授权废弃/替代/迁移清单、旧功能保留验证要求和异常差异记录。缺少这些内容时，不得让开发线程只围绕新增功能开发，也不得让审计线程只审新包当前可见功能，防止旧功能在资料缺口中静默丢失。

需求与审计线程向技术线程发出功能需求清单前，资料包必须沉淀本次审计基线，记录每个功能项的编号、用户目标、入口、交互路径、预期结果、状态/数据变化、成功/失败标准、回归范围和不可破坏旧功能。后续审计、三级测试、整改和终审必须引用该基线逐项核查，防止 A+B+C 发出后只按 A+C 当前实现验收而遗漏 B。

涉及资源、账号、端口、设备、项目、任务、订单、插件、工作流或业务对象时，资料包必须沉淀唯一事实源位置、资源服务接口、统一选择器入口、资源选择模式、资源执行策略、空库处理、状态更新时间、刷新规则、资源占用/互斥/并行规则、敏感信息隐藏要求和内部标识绑定方式。缺少这些资料时，不得让开发线程另建资源清单，也不得让审计线程只按内部 ID 验收。

新线程的接收回执至少包含：已读资料 Ref/路径；已枚举目录范围和排除规则；核心模块/入口/数据/运行链理解；Git/数据库/构建/回滚基线；已完成/未完成/未验证能力；资料冲突与阻断；下一步。仅列文件名、复述标题、阅读聊天摘要或不做项目遍历均不视为接收完成。

## 陈旧与冲突判定

资料包出现下列任一情况即标记为需复核：项目路径不存在；Git HEAD 与记录不同；数据库 schema/迁移版本不同；关键运行入口、配置或依赖变化；AIstudy 节点快照变化、无正文或 RAG 未配置；资料、源码、数据库、Git 和真实运行结果互相冲突。陈旧不等于失败，但不能当作已验证事实继续派发或放行。

## AIstudy 访问与分类

先读取全局 aistudy-mcp-access 技能。标准化开发流程课程为 49863edd-0522-4619-97b4-56695cd25ef9，导图为 mindmap_12be3b7f78da4a2f8cbf88227d747f22。完整节点分类、读取顺序和资料包字段见 references/aistudy-and-pack-index.md。

读取顺序固定为：当前课程/导图 → 目标节点上下文 → 需要时的完整正文 → 当前项目事实交叉核验。记录 Ref、快照/哈希、读取时间、正文状态和 RAG 状态。不得仅依赖节点标题、聊天摘要或短 Ref。

## 工具

- scripts/Initialize-ProjectKnowledgePack.ps1：基于真实项目根目录创建资料包 manifest 和变更目录；同名资料包拒绝覆盖。
- scripts/Test-ProjectKnowledgePack.ps1：只读检查 manifest、项目路径、Git 基线、资料路径和陈旧项；可用于启动、交接、审计和交付前。
- scripts/Get-ThreadKnowledgeBundle.ps1：按人事部、需求与审计、技术开发职责输出派发给新线程的资料清单、完整遍历任务和接收回执标准。
- scripts/Register-ProjectKnowledgePackDispatch.ps1：在线程创建成功后，将实际 ThreadId 与资料派发事实写入 manifest 和 changes 目录。
- references/change-record.md：资料变更单模板；只记录已证实变化，禁止敏感内容。
- references/aistudy-and-pack-index.md：AIstudy 标准化开发流程索引、资料包事实源和角色读取路由。
- references/thread-intake-contract.md：人事部派发与新线程完整遍历、接收报告的硬性契约。

## 禁止事项

- 不以资料包替代项目遍历、真实测试、需求文档或审计。
- 不自动写 AIstudy、数据库、Git、源码、运行配置或外部平台。
- 不记录密码、Token、Cookie、完整授权头、个人资料或绝对缓存路径。
- 不把未验证项、技术线程自报或历史聊天当成已验证事实。
- 不让多个线程同时编辑同一 manifest、变更单或同一项目模块；先由人事部登记占用与交接状态。
- 不在新线程未完成深度接收时发出正式开发、审计、发布或高风险操作任务。
- 用户级软件式交互同步规则：项目资料包必须沉淀普通用户主路径与交互基线，包括历史用户入口、当前正式入口、可选操作、状态、进度、结果、失败原因、下一步、回退路径、旧版功能保留情况和仅调试入口。涉及版本开发、审计、打包或发布时，资料包必须额外标明哪些能力是普通用户可完成的功能，哪些只是 `moduleId/action`、`taskId`、原始 JSON、调试 API、内部命令或底层能力。缺少用户级主路径基线时，不得让开发线程把底层能力当作用户功能完成，也不得让审计线程只审新包当前可见内容。
- 最新版入口资料包同步规则：项目资料包必须沉淀用户打开最新版的真实入口和可复用指令，包括 PowerShell 启动/验证/停止指令、工作目录、最新包或服务路径、快捷方式指向、旧进程/旧包/旧入口隔离情况、预期可见版本或变化、异常时的最小处理方式。涉及开发、打包、发布或审计交接时，缺少这些信息应标为资料缺口，不能让用户凭旧命令或旧快捷方式误开旧版本。
- 用户级实时性资料包同步规则：项目资料包必须沉淀用户功能的实时性与状态一致性事实，包括用户真实入口、状态事实源、数据刷新/同步机制、耗时操作进度反馈、任务结束与异常发现方式、页面/列表/汇总/任务记录一致性要求、历史/缓存/快照/推断结果的时间来源和有效性标识、失败/等待/阻塞/超时/资源占用处理路径、并发影响和最少操作路径。缺少这些信息时，不得让开发线程把静态页面、固定文案、一次性查询或底层命令可用包装成用户功能完成。
- 指令化路径与模块独立资料包规则：项目资料包必须沉淀功能的非鼠标指令化操作与验证路径，包括 PowerShell、CLI、API、MCP、脚本、HTTP 探针、程序内置指令、状态查询、日志核验、预期输出和失败判断。涉及多个具有独立性要求的模块时，资料包必须记录模块边界、仓库/发布/回滚/审计边界、分别修改验证提交/推送计划、跨模块对接关系和独立证据路径，避免后续混改、混测、混推。
- 完整需求与分段计划资料包规则：项目资料包必须沉淀完整功能需求、最终业务结果、完整功能链路、数据流、状态流、异常流、依赖关系、验收标准、回归范围、分段执行计划、阶段目标、完成标准、当前进度、剩余缺口、模块责任、风险变化和验收证据。缺少这些资料时，不得让技术线程只做最小实现，也不得让审计线程只审局部已实现内容。
- 四级审计技能资料包规则：资源资料包必须记录四个全局审计技能的用途、适用阶段、输入资料和输出证据要求：`audit-level-1-code-architecture`、`audit-level-2-business-interaction`、`audit-level-3-agentic-realpath-test`、`audit-level-4-final-governance`。当审计标准、功能基线、指令化测试、实时性、模块独立性或完整分段执行规则变化时，必须同步维护资料包与四个审计技能，避免不同审计工具依据不一致。
- 三级功能价值资料包规则：资源资料包必须为三级审计沉淀功能用途、用户目标、业务语义、输入条件、预期输出、数据事实源、状态变化、权限边界、正确结果样态和失败判断标准。缺少这些资料时，三级审计不得只凭接口返回、命令成功或页面内容判定通过。
- 未闭环项唯一索引规则：项目资料包必须为问题、缺陷、阻断项、测试失败、功能缺口、回归风险、资料缺口和人工介入项维护唯一索引、首次出现证据、责任模块、修复标准、验证方式、当前状态和后续处理路径。同一未闭环项第二次出现时，资料包不得新增重复普通记录，必须关联首次记录并标记为需要立即修复、升级处理或外部阻断确认，避免跨线程反复记录而不闭环。
- 审计基线资料包规则：资料包必须保存需求发出前的原始审计基线，并供二级、三级、四级审计逐项引用。审计和测试必须按每个功能项的用户用途自行设计，不得套固定测试模板，不得只根据技术线程已实现内容或当前包可见内容验收。
- 源库与资源选择资料包规则：资料包必须保存资源事实源、资源选择器、资源策略声明和用户级选择验收标准。凡资料显示系统已有真实源库，审计不得接受“用户输入内部编号”作为常用操作主路径。
