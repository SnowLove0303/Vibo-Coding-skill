# 新线程资料包接收契约

## 人事部创建线程前

1. 核验 manifest、资料源路径、Git 基线、陈旧项和现有线程状态。
2. 按目标职责生成资料清单，并将它与项目根目录、当前事实、已知冲突和接收要求一并发送。
3. 创建成功后登记真实 ThreadId、资料派发时间和待接收状态。

## 新线程必须完成

1. 阅读 Global Memory、manifest、最近变更单、职责专属 AIstudy 正文及当前任务资料。
2. 用 rg --files 或等效方式完整枚举所有项目资料源；说明排除规则，不能只读点名文件。
3. 读取适用 AGENTS.md、README、入口、核心模块、配置、数据存储、测试、Git 及当前运行入口；技术和需求审计线程必须形成调用/数据/业务链理解。
4. 对资料、源码、Git、数据库和运行事实做交叉核验，标出冲突、过期、无正文、RAG 未配置和未验证项。
5. 提交接收报告。未完成前状态只能是接收中，不能领取正式任务。

## 接收报告字段

已读资料；项目遍历范围；核心系统理解；当前基线；已完成能力；未完成/未验证能力；冲突与阻断；角色边界；下一步只读或正式动作。
用户级软件式交互接收项：新线程接收资料包时，必须说明普通用户主路径、真实入口、状态/进度/结果/失败/下一步/回退路径、旧版功能入口保留情况、内部/调试入口、底层能力与用户功能完成之间的差异。若资料只给出 `moduleId/action`、`taskId`、原始 JSON、调试 API 或内部命令，必须标为资料缺口或技术诊断路径，不能直接当成正式用户功能需求。

审计资料接收项：审计线程接收任务时，资料包必须包含技术执行开发线程的完整执行记录和反馈，包括任务理解、实施步骤、修改文件、关键命令、测试/自测记录、失败与重试记录、问题反馈、未解决风险、人工介入项、回滚点、逐项功能实现汇报和既有功能影响说明。缺少这些材料时，接收结论只能标为资料缺口，不能直接开始放行审计。

一次性接收项：新线程接收需求、审计反馈或整改任务时，必须确认资料包包含完整用户视角功能清单、旧功能基线、必须实现项、禁止破坏项、已发现不足、疑似风险、真实入口、数据/权限/配置影响、回归范围、人工介入项、通过标准、失败标准、执行记录和证据路径。缺少会导致同一目标反复返工的信息时，必须一次性提出资料缺口。
最新版入口接收项：新线程接收涉及本地应用、EXE、服务、桌面程序、前端本地服务、CLI 工具或用户会手动打开入口的任务时，必须确认资料包包含用户打开最新版的真实入口、PowerShell 启动/验证/停止指令、工作目录、最新包或服务路径、快捷方式指向、旧进程/旧包/旧入口隔离情况、预期可见版本或变化、异常时的最小处理方式。缺少这些信息时必须标为资料缺口，不能默认用户会看到最新变更。
用户级实时性接收项：新线程接收面向用户的应用、服务、调度层、模块或自动化任务时，必须确认资料包包含用户真实入口、状态事实源、数据刷新/同步机制、耗时操作进度反馈、任务结束与异常发现方式、页面/列表/汇总/任务记录一致性要求、历史/缓存/快照/推断结果的时间来源和有效性标识、失败/等待/阻塞/超时/资源占用处理路径、并发影响和最少操作路径。缺少这些信息时必须标为资料缺口，不能默认功能具备实时用户体验。
指令化与模块独立接收项：新线程接收功能开发、审计或整改任务时，必须确认资料包包含非鼠标指令化操作与验证路径，包括 PowerShell、CLI、API、MCP、脚本、HTTP 探针、程序内置指令、状态查询或日志核验，以及预期输出、失败判断和回归方式。涉及多模块时，必须确认模块边界、独立性要求、仓库/发布/回滚/审计边界、分别修改验证提交/推送计划、跨模块对接关系和独立证据路径。
完整需求与分段计划接收项：新线程接收复杂功能或模块对接任务时，必须确认资料包包含完整功能需求、最终业务结果、完整功能链路、数据流、状态流、异常流、依赖关系、验收标准、回归范围、分段执行计划、阶段目标、完成标准、当前进度、剩余缺口、模块责任、风险变化和验收证据。缺少这些信息时必须标为资料缺口，不能只按局部最小实现推进。
指令化与模块独立接收项：新线程接收功能开发、审计或整改任务时，必须确认资料包包含非鼠标指令化操作与验证路径，包括 PowerShell、CLI、API、MCP、脚本、HTTP 探针、程序内置指令、状态查询或日志核验，以及预期输出、失败判断和回归方式。涉及多模块时，必须确认模块边界、独立性要求、仓库/发布/回滚/审计边界、分别修改验证提交/推送计划、跨模块对接关系和独立证据路径。
完整需求与分段计划接收项：新线程接收复杂功能或模块对接任务时，必须确认资料包包含完整功能需求、最终业务结果、完整功能链路、数据流、状态流、异常流、依赖关系、验收标准、回归范围、分段执行计划、阶段目标、完成标准、当前进度、剩余缺口、模块责任、风险变化和验收证据。缺少这些信息时必须标为资料缺口，不能只按局部最小实现推进。
